# تانل GRE بهینه (بر پایه vatanhost/gre)

**راهنمای کامل:** نحوه کار اسکریپت، کارهای انجام‌شده روی سرورها، دستورالعمل‌ها و عیب‌یابی در [GUIDE.md](GUIDE.md) آمده است.

## نصب
روی هر سرور (اول سرورهای خارج، بعد ایران) این را اجرا کنید:
```bash
bash <(curl -sSL https://raw.githubusercontent.com/tradeahadi-cmyk/gre-tunnel/main/gre-install.sh)
```
- **Tunnel number:** برای آلمان 1، برای ترکیه 2. روی هر دو طرفِ یک تانل باید یکی باشد.
- **Ports:** پورت‌هایی که از ایران به این سرور خارج می‌رود، مثلاً `8388,2053` (بازه هم می‌شود: `20000:20100`). روی سرور خارج هم **همان لیست** را بدهید.
- روی ایران برای هر سرور خارج یک بار اجرا کنید. پورت دو سرور نباید تکراری باشد.
- `all` (همه پورت‌ها غیر از SSH) فقط وقتی مجاز است که ایران فقط یک سرور خارج داشته باشد.

اسکریپت خودش تانل قدیمی `vatan-m2` و قوانینش را پاک می‌کند، حتی اگر در rc.local یا crontab یا rules.v4 ذخیره شده باشد (از فایل‌ها نسخه `.bak` می‌ماند).

نسخه‌ها و تغییرات هر نسخه در [CHANGELOG.md](CHANGELOG.md) است. هر نسخه در پوشه `versions/` هم نگه داشته می‌شود؛ برای نصب یک نسخه مشخص (مثلاً اگر نسخه جدید مشکل داشت):
```bash
bash <(curl -sSL https://raw.githubusercontent.com/tradeahadi-cmyk/gre-tunnel/main/versions/v2.5.0/gre-install.sh)
```

## بدون دسترسی به گیت‌هاب
- **روی سروری که اسکریپت را دارد:** از نسخه 2.5.0، منو روی خود سرور هم ذخیره می‌شود (با گزینه 1 یا 5). بدون اینترنت کافی است بزنید:
```bash
gre-install
```
  همه گزینه‌ها بدون اینترنت کار می‌کنند: نصب تانل جدید، حذف، وضعیت، عیب‌یابی و حذف کامل. فقط برای رفتن به نسخه جدیدتر باید فایل جدید را از یکی از دو راه زیر برسانید.
- **لینک جایگزین (jsDelivr):** اگر گیت‌هاب باز نمی‌شود ولی jsDelivr باز است:
```bash
bash <(curl -sSL https://cdn.jsdelivr.net/gh/tradeahadi-cmyk/gre-tunnel@main/gre-install.sh)
```
  jsDelivr این لینک را تا ۱۲ ساعت نگه می‌دارد، پس ممکن است نسخه جدید تا ۱۲ ساعت دیرتر آنجا برسد. نسخه در بالای منو نوشته شده است.
- **کپی دستی:** فایل را از کامپیوترتان (مثلاً با WinSCP) یا از سرور دیگری که آن را دارد کپی کنید و اجرا کنید:
```bash
scp /usr/local/sbin/gre-install root@IP-SERVER:/root/gre-install.sh   # روی سروری که فایل را دارد
bash /root/gre-install.sh                                            # روی سرور مقصد
```

## تست
```bash
gre-tunnel check 1                 # روی ایران یا خارج
gre-tunnel version                 # نسخه نصب‌شده
gre-tunnel diag 1                  # اگر کار نمی‌کند: علت را پیدا می‌کند (روی هر دو سرور)
systemctl status gre-tunnel@1
journalctl -t gre-watchdog         # گزارش‌های واچ‌داگ
```

## به‌روزرسانی
همان دستور نصب و گزینه 5. تنظیمات عوض نمی‌شود و کاربران قطع نمی‌شوند. روی هر سه سرور بزنید. تانل رمزدار هم به‌روز می‌شود. اگر xray آن باید ری‌استارت شود، اول می‌پرسد.

## حذف
- **حذف یک تانل:** همان دستور نصب و گزینه 2.
- **حذف کامل (گزینه 6):** همه تانل‌های این اسکریپت (GRE و رمزدار) و هر چیزی را که نصب کرده پاک می‌کند: سرویس‌ها، قوانین فایروال، اینترفیس‌های vgre، فایل‌ها و تنظیمات BBR. سرور به حالت قبل از نصب برمی‌گردد. x-ui، SSH و سرویس‌های دیگر دست نمی‌خورند. کاربرانی که روی تانل‌ها هستند قطع می‌شوند، برای همین باید `yes` تایپ کنید:
```bash
printf '6\nyes\n' | bash <(curl -sSL https://raw.githubusercontent.com/tradeahadi-cmyk/gre-tunnel/main/gre-install.sh)
```
  `ip_forward` و اندازه جدول conntrack روی سرور ایران تا ریبوت بعدی همان‌طور می‌مانند، چون خاموش کردنشان ممکن است سرویس‌های دیگر را قطع کند. اگر مقدار قبلی BBR معلوم نباشد (نصب با نسخه‌های قبل از 2.4.0)، BBR هم تا ریبوت بعدی می‌ماند. اگر قوانین فایروال در `/etc/iptables/rules.v4` ذخیره شده باشند، قوانین تانل از آنجا هم پاک می‌شوند (نسخه پشتیبان: `rules.v4.gre-bak`). تانل قدیمی vatan برگردانده نمی‌شود.

## چه چیزی عوض شده (نسبت به اسکریپت vatanhost)
- بعد از ریبوت خودکار بالا می‌آید (سرویس systemd).
- فقط پورت‌های انتخابی فوروارد می‌شود؛ بسته‌های GRE، ICMP و SSH هرگز فوروارد نمی‌شوند.
- کاربران فقط به همان پورت‌های سرور خارج می‌رسند و سرویس‌های دیگر آن (مثل پنل) از طریق IP ایران باز نمی‌شوند. سرور خارج همان پورت‌ها را از تانل صریحاً می‌پذیرد. پینگ از بیرون بسته است.
- MTU برابر 1420 و MSS ثابت 1380، تا اتصال‌ها روی مسیرهای با MTU کمتر گیر نکنند.
- با ufw و Docker تداخل ندارد (GRE و فوروارد صریحاً مجاز می‌شود).
- جدول conntrack روی ایران بزرگ‌تر می‌شود تا با کاربر زیاد بسته‌ها دور ریخته نشوند.
- واچ‌داگ هر ۳۰ ثانیه: اگر چیزی (مثلاً `iptables -F`) قوانین یا تانل را پاک کرده باشد، دوباره می‌سازد. اگر سرِ دیگر جواب ندهد فقط در لاگ ثبت می‌کند و تانل را ری‌استارت نمی‌کند، چون ری‌استارت همه کاربران را قطع می‌کند و GRE را درست نمی‌کند.

## تانل رمزدار (VLESS + WebSocket + TLS)، از نسخه 3.0.0
در بعضی دیتاسنترها و اپراتورهای ایران بخشی از بسته‌های GRE در مسیر گم می‌شود و کاربران قطعی چند ثانیه‌ای می‌بینند. تانل رمزدار ترافیک پورت‌های انتخابی را داخل اتصال‌های معمولی TLS به سرور خارج می‌برد. کنار GRE نصب می‌شود و GRE دست نمی‌خورد، پس هر پورت را می‌شود جدا جابجا کرد و هر وقت خواستید برگرداند.

**نصب:**
1. روی سرور خارج: `gre-install`، گزینه 7، `FOREIGN`، شماره تانل (همان شماره GRE به همین سرور)، IP ایران، پورت‌های سرویس روی همین سرور (مثلاً `43773,443`)، پورت تانل (پیش‌فرض 2083)، نام دامنه (اختیاری) و IP همین سرور. در آخر یک کد چاپ می‌شود که با `XT1-` شروع می‌شود. این کد کلید تانل است، جایی منتشرش نکنید.
2. روی ایران: `gre-install`، گزینه 7، `IRAN`، همان شماره، و کد را paste کنید.
3. تا اینجا هیچ پورتی روی تانل رمزدار نیست و همه چیز مثل قبل از GRE می‌رود. برای بردن یک پورت روی ایران: گزینه 8، یا
```bash
xray-tunnel on 1 43773     # اتصال‌های جدید پورت 43773 از تانل رمزدار
xray-tunnel off 1 43773    # برگشت به GRE
```

**رفتار:**
- جابجایی فقط دستی است و با `on` و `off` (یا گزینه 8) انجام می‌شود. اتصال‌های باز روی مسیر قبلی‌شان می‌مانند و فقط اتصال‌های جدید از مسیر جدید می‌روند، پس با جابجایی کسی قطع نمی‌شود.
- اگر تانل رمزدار قطع شود، پورت **خودکار به GRE برنمی‌گردد**. کاربران آن پورت تا برگشتن تانل، یا تا وقتی خودتان `off` بزنید، وصل نمی‌شوند. قطع و وصل شدن در `journalctl -t xray-tunnel` ثبت می‌شود و `xray-tunnel check 1` آن را نشان می‌دهد. اگر تانل جواب ندهد، `on` پورت را جابجا نمی‌کند.
- هر اتصال کاربر یک اتصال TLS جدا دارد (بدون mux)، پس یک کاربر کُند بقیه را کُند نمی‌کند.
- هر ۳۰ ثانیه قوانین فایروال تانل دوباره گذاشته می‌شود (مثلاً بعد از `iptables -F` یا ریبوت)، ولی هیچ پورتی جابجا نمی‌شود.
- یک xray جدا با سرویس `xray-tunnel@N` اجرا می‌شود که کپی xray خودِ x-ui است. x-ui و xray آن دست نمی‌خورند و آپدیت x-ui روی تانل اثری ندارد.
- پورت تانل روی سرور خارج فقط برای IP ایران باز است. اگر سرور خارج فایروال ابری دارد (مثلاً Hetzner Firewall)، این پورت را آنجا هم برای IP ایران باز کنید.
- گواهی TLS روی سرور خارج ساخته می‌شود و ایران اثر انگشت همان گواهی را قبول می‌کند، پس دامنه و گواهی واقعی لازم نیست. نام دامنه فقط در handshake دیده می‌شود.
- سرور خارج کاربران تانل رمزدار را با IP `127.0.0.1` می‌بیند (مثل `10.200.N.2` در GRE).

**دستورها:**
```bash
xray-tunnel check 1          # روی هر دو سرور
systemctl status xray-tunnel@1
journalctl -t xray-tunnel    # جابجایی پورت‌ها و قطع و وصل تانل
journalctl -u xray-tunnel@1  # لاگ xray
```
- **تغییر تنظیمات:** دوباره گزینه 7. کلیدها عوض نمی‌شوند. اگر برای تنظیمات جدید باید xray ری‌استارت شود و اتصال باز دارد، اول می‌پرسد، چون ری‌استارت اتصال‌های باز تانل رمزدار را قطع می‌کند. اگر پورت‌ها را روی سرور خارج عوض کردید، کد جدید را روی ایران هم بدهید.
- **حذف:** گزینه 9. روی ایران اول همه پورت‌ها به GRE برمی‌گردند. حذف کامل (گزینه 6) هم آن را پاک می‌کند.

## آی‌پی‌های تانل
| تانل | ایران | خارج |
|---|---|---|
| 1 | 10.200.1.2 | 10.200.1.1 |
| 2 | 10.200.2.2 | 10.200.2.1 |

## نکته‌ها
- سرور خارج همه کاربران را با IP `10.200.N.2` می‌بیند، پس «محدودیت IP» پنل کار نمی‌کند (در اسکریپت قبلی هم همین بود). اگر fail2ban دارید، `10.200.0.0/16` را در `ignoreip` بگذارید.
- برای تغییر MTU، مقدار `MTU=` را در `/etc/gre-tunnel/N.conf` روی هر دو طرف عوض کنید و `systemctl restart gre-tunnel@N` بزنید.
